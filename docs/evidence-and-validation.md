# 小满项目｜可核验成果与验证边界

> 面向 FDE / AI 数字化落地岗位。更新时间：2026-11-05。本文只记录已有项目事实，不把设计方案、离线测试、本地模拟和真实业务验收混为一谈。

## 一句话介绍

小满是从直播电商中控一线流程出发搭建的业务自动化与 AI 副驾项目。我负责发现业务问题、拆解需求、设计流程与模块、定义数据口径和验收标准，并通过 AI Coding 协作推进实现、联调、测试和迭代。

项目重点不是让大模型直接接管直播间，而是把模型放在适合的理解环节，把确定性操作交给规则与工具，并对关键结果做状态核验。

## 二、最值得面试展示的三条证据链

### 1. AI 副驾：先理解问题，再决定能不能回答

业务问题：直播公屏评论经常省略商品上下文，例如“这个有黑色吗”“一号链接能看看吗”。只把单条评论交给模型，容易把当前讲解商品误认为用户询问的商品，也容易臆测价格或库存。

方案：
1. 先识别评论意图，例如颜色、价格、材质、商品比较、有货咨询。
2. 结合主播口播 ASR 和中控讲解事件补充时间上下文。
3. 通过本场完整商品目录与商品名称定位目标商品。
4. 只有存在可信商品资料时才生成候选提示；缺少实时库存、价格或活动依据时，明确转为待核实。

离线评测：32 条样本中，30 条返回有效结果，26 条与预期分类匹配；26/32 = 81.25%。该数值是离线样本匹配率，不是生产环境准确率。

当前限制：三源上下文对齐仍在迭代；商品完整列表和名称映射尚未完成全量验收；副驾当前不直接回答未经核实的商品事实。

### 2. 数据自动化：从单次脚本走向有状态的混合工作流

业务问题：中控需要按半小时 / 整点节奏从不同业务页面读取指标，再写入既有 Excel。页面、指标口径、金额单位和直播场次变化都可能导致静默错误。

方案：
- 半点链：每 30 分钟采集 8 项直播指标。
- 整点链：每 60 分钟采集 6 项千川指标。
- 对字段映射、金额单位、指标口径、缺失值和跨场次累计值进行校验。
- V2 引入 Metric / Preset / Run / Snapshot / History 等模型概念，以及运行锁、来源身份、阶段 checkpoint、结果冻结和 cleanup。

阶段性验收：
- Phase 6：两条业务链路各 4/4 次成功验证，21 项测试通过。
- Phase 10：2026-10-10 的一次真实定时混合工作流中，先完成千川来源，再切换罗盘来源，最终形成 6 项冻结结果、2 个来源 Snapshot 和 1 条 History；Run 终态 success，cleanup complete。
- Phase 10 closure 记录了 31 个自动化测试脚本通过，以及恢复测试 56 项通过。

注意：Phase 10 原始导出、完整报告和独立核验文件保留在本地；Git 仓库中的 evidence manifest 记录了文件名、大小和 SHA-256，不包含原始业务值。因此公开作品集展示的是脱敏验收摘要，不声称招聘方可以仅凭公开仓库复现那次真实直播运行。

### 3. SOP / 语音工具：把动作变成可检查的流程

- DOM / SOP：在本地孪生页面复刻关键结构与交互状态，以 elements / flows / engine 分层表达元素映射和流程步骤。首条流程为“复制商品 ID → 搜索 → 打开库存抽屉 → 查看库存”。
- 语音触发：使用轻量本地 ASR 识别讲解触发词，再与商品索引关联；设计误触拦截、Dry Run、授权和日志。完成过单次真实点击验证，但不把它描述为全量生产稳定。
- 经验教训：曾定位音频路由导致识别结果前段正确、后段混乱的问题，根因是电脑接收了自身麦克风音频；修复应先检查音源链路，而不是盲目更换模型。

## 三、个人负责内容与技术协作边界

本人主要负责：
- 一线业务问题识别、用户任务拆解和需求优先级。
- 数据字段、指标口径、商品身份和流程边界定义。
- Agent / 自动化方案设计、模块拆分和工具调用边界。
- 异常场景、测试用例、验收标准、联调与业务结果核对。
- 根据真实反馈迭代范围，例如不让副驾回答当前系统无法可靠读取的单 SKU 实时库存。

代码实现采用 Codex 等 AI Coding 工具协作推进；本人具备基础代码阅读、修改、API / JSON 对接、排错和测试实践。不将 AI 生成代码包装成独立手写完整后端项目。

## 五、验证边界与未完成事项

为避免误解，以下事项不作为已完成成果宣传：
- AI 副驾尚未完成真实直播公屏的长期在线准确率验证。
- 三源上下文对齐与全量商品名称映射仍在开发。
- 知识模块目前是离线基础模块，不能查询实时 SKU 库存或实时价格。
- DOM / SOP 首条流程在本地孪生页面验证，不代表正式后台所有动作均已验收。
- 语音触发只完成预演和单次真实点击验证，不代表全场景稳定。
- Phase 10 的 Worker 休眠 / 重启恢复与真实 stall reload 路径没有由该次真实验收覆盖。
- 原始 Phase 10 业务数据和 AI 评测样本未公开；公开仓库不包含公司业务数据、真实客户评论、账号 Cookie 或 API 密钥。

## 六、建议的招聘方核验方式

1. 先阅读本仓库的项目案例和系统架构，了解业务问题、模块关系与本人贡献。
2. 阅读 3–5 分钟演示脚本，按脱敏演示环境查看副驾意图识别、数据工作流和 SOP 流程。
3. 如需技术核验，可申请查看私有 POC 仓库中的模型、状态管理、调度器和测试脚本；真实业务数据只在授权且脱敏的情况下展示。

项目核心不是“让模型自动做所有事”，而是能从业务现场识别问题，把它拆成有输入、有状态、有边界、有验收结果的 AI / 自动化工作流。
