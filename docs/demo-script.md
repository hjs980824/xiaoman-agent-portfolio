# 小满作品集演示脚本（建议 4–5 分钟）

> 面向 FDE / AI 应用实施岗位。演示重点是业务问题、系统设计、个人贡献和验收边界，不需要现场操作真实直播间。

## 拍摄前检查

- 使用脱敏账号、模拟数据或已获授权的演示环境。
- 隐藏店铺名称、直播间 ID、账号昵称、客户评论、Cookie、请求头、API Key 和内部链接。
- 画面中明确标注“真实业务试跑 / 本地模拟 / 离线测试”。
- 不在公开录屏中执行可能影响真实直播的点击、弹链、轮评、福袋或商品排序操作。
- 录制前检查桌面通知和浏览器标签，避免暴露内部资料。

## 0:00–0:35｜业务背景

展示：直播中控实际任务链路（用示意图即可）。

讲解：

“这个项目来自直播电商中控的一线工作。中控需要在多个页面之间切换，完成数据记录、商品操作和评论协助。我希望把高频重复工作沉淀成自动化流程，并把 AI 用在适合的理解和辅助决策环节。”

## 0:35–1:45｜AI 评论副驾（主展示）

展示：
- 脱敏评论样例：“这个有黑色吗”“一号链接能看看吗”。
- 意图识别结果。
- 公屏评论、主播口播 ASR、中控讲解事件三源上下文示意。
- 商品目录定位与待核实分支。

讲解：

“副驾不是只看一条评论就回答。它需要结合公屏评论、主播口播和中控讲解事件，再通过本场商品目录定位用户真正问的是哪一款。当前先做意图识别和上下文设计，不让模型编造实时库存或价格。离线样本 32 条，30 条返回有效，26 条分类匹配，匹配率 81.25%，这不是线上准确率。”

## 1:45–2:45｜数据自动化（工程落地）

展示：
- 半点 8 项 / 整点 6 项指标字段。
- V2 的 Preset / Run / Snapshot / History 结构。
- Phase 10 验收摘要中的一次混合来源执行结果（脱敏）。

讲解：

“这里不是简单复制数字，而是先明确指标口径和来源，再把一次执行建模成 Run。千川和罗盘是两个来源，分别形成 Snapshot，结果冻结后再进入一条 History。Phase 10 有一次真实定时混合来源验收，六项结果、两个 Snapshot、一条 History，清理状态完成。长期稳定性和 Worker 重启恢复仍需进一步验证。”

## 2:45–3:35｜SOP 与工具边界

展示：
- 本地孪生页面。
- SOP 的元素映射与流程配置。
- 商品 ID 搜索、打开库存抽屉、查看库存的步骤。

讲解：

“我没有把自动化理解成坐标连点，而是尽量把页面动作变成可复用步骤。当前首条 SOP 在本地孪生页面跑通，正式后台的全量动作仍需逐项验收。”

## 3:35–4:20｜个人贡献与协作方式

讲解：

“我主要负责业务需求拆解、流程设计、字段口径、模块优先级和验收标准，使用 Codex 等 AI Coding 工具协作实现。我会区分离线测试、模拟页面测试和真实业务验证，不把测试通过直接说成生产稳定。”

## 4:20–4:50｜总结

讲解：

“小满让我把业务经验转化成可复用的系统设计：数据有口径、商品有身份、上下文有来源、工具有边界、结果可核验。这套方法可以迁移到企业知识助手、运营自动化和其他 Agent 工作流。”
