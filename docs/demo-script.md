# 小满作品集演示脚本（建议 3–5 分钟）

## 拍摄前检查

- 使用脱敏账号、模拟数据或已获授权的演示环境。
- 隐藏店铺名称、直播间 ID、账号昵称、客户评论、Cookie、请求头、API Key 和内部链接。
- 画面中明确标注“真实业务试跑 / 本地模拟 / 离线测试”。
- 不在公开录屏中执行可能影响真实直播的点击、弹链、轮评、福袋或商品排序操作。
- 录制前检查桌面通知和浏览器标签，避免暴露内部资料。

## 0:00–0:35｜业务背景

讲解参考：

“这个项目来自直播电商中控的一线工作。中控需要在多个页面之间切换，完成数据记录、商品操作和评论协助。我希望把高频重复工作沉淀成自动化流程，并把 AI 用在适合的理解和辅助决策环节。”

## 0:35–1:25｜数据自动化

展示：

- 数据采集页面或采集方案。
- 半点/整点指标字段。
- 表格写入、截图或历史记录。

讲解参考：

“这里把不同来源的数据按指标口径采集，并保留时间和场次信息。跨场次累计值不能简单混算，所以场次隔离和结果复核是重要的业务约束。”

## 1:25–2:15｜SOP 与工具边界

展示：

- SOP 流程步骤。
- click、input、筛选/取消筛选等动作配置。
- 执行前参数检查或执行后状态核验。

讲解参考：

“我没有把自动化理解成坐标连点，而是尽量把页面动作变成可复用的步骤。涉及直播状态变化的动作需要校验目标、执行结果和页面状态。”

## 2:15–3:20｜AI 评论副驾

展示：

- 脱敏评论样例。
- 意图识别结果。
- 主播口播上下文与商品目录映射。
- 候选回答或待核实提示。

讲解参考：

“副驾不是只看一条评论就回答。它需要结合公屏评论、主播口播和本场商品目录。当前阶段先聚焦意图识别和上下文对齐，不让模型编造实时库存或价格。”

## 3:20–4:00｜个人贡献与验收边界

讲解参考：

“我主要负责业务需求拆解、流程设计、字段口径、模块优先级和验收标准，使用 AI Coding 协作实现。我会区分离线测试、模拟页面测试和真实业务验证，不把测试通过直接说成生产稳定。”

## 4:00–4:30｜总结

讲解参考：

“小满让我把业务经验转化成可复用的系统设计：数据有口径、商品有身份、上下文有来源、工具有边界、结果可核验。后续可以把这套方法迁移到企业知识助手、运营自动化和其他 Agent 工作流。”
